# Komyut

A free, static, mobile-first commuter guide for Metro Cebu, Philippines. It shows jeepney codes and routes, city and provincial bus routes, popular places with step-by-step *sakay* directions, a trip planner, and fare estimates (including taxi) on an interactive map centered on Cebu City.

No paid APIs, no API keys, no backend, no database, no login. Plain HTML, CSS and vanilla JavaScript (ES modules). Map: [Leaflet](https://leafletjs.com) 1.9.4 from cdnjs with OpenStreetMap tiles.

> Routes are approximate. Confirm with the driver or barker. Fares are estimates; the fare guide posted inside the vehicle settles any difference.

## Features

- **Map:** layer toggles (Jeepney, City bus, Provincial bus, Terminals, Places), route highlight with fade, popups, search, a scrollable grouped route list, and **Clear selection** (clears the route, pin popups and trip plan).
- **Plan a trip:** choose a start and an end (places, bus terminals, provincial destinations). The planner suggests walking, direct rides, one-transfer rides and a taxi, with step-by-step text, fare estimates and the chosen option drawn on the map.
- **Jeepney / Bus tabs:** searchable cards, "Show on map". The Bus tab also lists provincial routes from the South and North bus terminals.
- **Places tab:** 20 destinations with category filter and commute steps per starting point.
- **Fares tab:** fare table (jeepney, city bus, provincial ordinary bus, taxi), discount info, and a calculator that includes a taxi option.
- Dark mode via `prefers-color-scheme`, system font stack, keyboard accessible, works on slow 4G.

## Run locally

ES modules need HTTP (they do not run from `file://`):

```
python -m http.server 8000
```

Open http://localhost:8000.

## Deploy (GitHub + Vercel)

1. Create a GitHub repo and push all files (the repo root is the site root).
2. In Vercel: **Add New Project** → import the repo → Framework Preset **Other** → no build command → output directory **.** → **Deploy**.
3. Every `git push` to `main` redeploys automatically.
4. Optional: keep `.github/ISSUE_TEMPLATE/route-fare-correction.yml` so people can file "Route/Fare correction" issues.

`vercel.json` is not needed. File names are case-sensitive on Vercel.

## Make the route lines accurate (snap to roads)

The `waypoints` in `data/*.json` are hand-placed estimates, so lines drawn from them can cut across buildings or water. They are drawn **dashed**. To draw accurate **solid** lines:

1. On your own computer (Python 3.8+, no packages needed), from the repo root run:

   ```
   python tools/snap-routes.py
   ```

   The script asks a free public OSRM routing server for the road geometry through each route's waypoints, simplifies it, and writes `data/paths.json`. It makes one request per route with a pause between requests; run it once, not in a loop.
2. Check the output. A line marked `<-- check` came out much longer than the rough line: move that route's waypoints closer to the right road and run `python tools/snap-routes.py --only jeepney:04L`.
3. Commit `data/paths.json`. The site automatically prefers a snapped path over the waypoints, and the trip planner uses it too.

Options: `--only jeepney:04L bus:MY01`, `--server https://routing.openstreetmap.de/routed-car`, `--radius 400`, `--tolerance 4`, `--fresh`. Provincial routes use a larger snapping radius (`--provincial-radius`).

## Project structure

```
index.html            app shell (tabs: Map | Jeepney | Bus | Places | Fares | About)
css/styles.css
js/app.js             bootstrap, tab navigation, error handling
js/map.js             Leaflet init, layers, markers, route highlight, trip-plan drawing
js/data.js            fetch + validate JSON, with fallbacks; fares loader
js/jeepney.js         Jeepney tab
js/bus.js             Bus tab (terminals, city routes, provincial routes)
js/places.js          Places tab
js/fares.js           Fares tab + calculator (incl. taxi)
js/plan.js            Plan a trip (map sidebar)
data/jeepney.json     jeepney routes (data/jeepney-2.json holds more)
data/bus.json         terminals + city bus routes
data/bus-provincial.json   provincial routes from the South and North terminals
data/places.json      places (data/places-2.json holds more)
data/fares.json       fare rules
data/paths.json       snapped road paths (generated by tools/snap-routes.py; empty until you run it)
tools/snap-routes.py  optional authoring script, not part of the site
debug.html            optional diagnostics page; delete when the site works
```

Every tab fails on its own: if a JSON file is missing or invalid, that tab shows a friendly message and the others keep working. If Leaflet fails to load, the map tab shows a text-only route list and the trip planner still works.

## Data schemas

All data lives in `/data`. Never hardcode data in JS.

**jeepney.json** (array; `jeepney-2.json` has the same shape)

```json
{ "code": "04L", "name": "Lahug – SM City Cebu", "type": "traditional|modern",
  "from": "", "to": "", "via": [""], "waypoints": [[10.32, 123.89]],
  "color": "#c2185b", "operating_hours": "", "confidence": "verified|community|unverified", "notes": "" }
```

**bus.json** and **bus-provincial.json** (provincial file has only `routes`, each with `"category": "provincial"`)

```json
{ "terminals": [{ "id": "csbt", "name": "", "lat": 0, "lng": 0, "address": "",
                  "operators": [""], "destinations": [""], "confidence": "", "notes": "" }],
  "routes": [{ "id": "MY01", "category": "city|provincial", "operator": "", "from": "", "to": "", "via": [""],
               "waypoints": [[0, 0]], "bus_type": "ordinary|aircon",
               "est_duration_min": null, "color": "#37474f", "confidence": "", "notes": "" }] }
```

**places.json** (array; `places-2.json` has the same shape)

```json
{ "id": "", "name": "", "category": "mall|park|theme_park|historic|religious|market|beach|other",
  "city": "Cebu City|Mandaue|Lapu-Lapu|Talisay|Consolacion|Liloan|Minglanilla|Naga",
  "lat": 0, "lng": 0, "description": "", "entrance_fee": "", "hours": "",
  "how_to_commute": [{ "from": "", "steps": [
    { "mode": "jeepney|bus|taxi|walk|tricycle|habal-habal|ferry", "line": "04L", "instruction": "", "est_fare": null } ] }],
  "confidence": "", "notes": "" }
```

**fares.json**

```json
{ "effective_date": "2026-09-28", "source_note": "", "checked_on": "",
  "jeepney_traditional": { "min_fare": 14, "min_km": 4, "per_km": 2 },
  "jeepney_modern": { "min_fare": 17, "min_km": 4, "per_km": 2.4 },
  "discount_pct": 20, "discount_applies_to": [""],
  "bus": { "ordinary": { "min_fare": 15, "min_km": 5, "per_km": 2.49 },
           "aircon": { "min_fare": 18, "min_km": 5, "per_km": 2.98 } },
  "provincial_bus": { "ordinary": { "min_fare": 12, "min_km": 5, "per_km": 2.2 } },
  "provincial_note": "",
  "taxi": { "flag_down": 65, "per_km": null, "note": "" },
  "rounding": { "step": 0.25, "mode": "nearest|up", "note": "" },
  "distance_estimate": { "road_factor": 1.3 },
  "bus_note": "", "taxi_note": "", "tricycle_note": "", "habal_note": "" }
```

Fare rule: `fare = min_fare` if distance ≤ `min_km`, otherwise `min_fare + ceil(distance − min_km) × per_km`; then the discount (if chosen); then rounding. Distance is a straight-line (Haversine) estimate × `road_factor`, labelled as an estimate in the UI. A rate set to `null` shows "Rate not yet verified". When the regular-taxi `per_km` is `null`, the calculator shows the flag-down and lets the user type their own meter rate.

**paths.json** (generated)

```json
{ "version": 1, "generated": "2026-11-03", "server": "https://router.project-osrm.org",
  "paths": { "jeepney:04L": [[10.3275, 123.8995], [10.3274, 123.8996]], "bus:MY01": [[0, 0]] } }
```

Keys are `jeepney:<code>` and `bus:<id>`.

## How the trip planner works

It runs in the browser on the route lines already loaded: it finds routes within 800 m of the start and the end, and suggests direct rides and rides with one transfer where two lines pass within 350 m of each other. Time is estimated from walking (80 m/min), riding (about 15 km/h) and waiting (6 min per boarding). It is only as accurate as the route lines (dashed = rough), so it always says to confirm with the driver or barker.

## Confidence levels

| Level | Meaning | UI badge |
|---|---|---|
| `verified` | Endpoints agree across two or more independent sources. Not an official LTFRB check. | Verified (multiple sources) |
| `community` | One source, or details partly inferred. | Community-reported |
| `unverified` | Location or route needs confirmation, or the pin is approximate. | Unverified – help us confirm |

Invalid or missing confidence values are shown as `unverified`.

## Contributing

Do not invent codes, routes or fares. If unsure, use `"confidence": "unverified"` and say why in `notes`.

- **Report a problem:** open a ["Route/Fare correction" issue](https://github.com/Splashzzz/Komyut/issues/new?template=route-fare-correction.yml) with a source or the date you rode it.
- **Add data:** open a pull request that edits files in `/data` in small batches (5–8 entries). Check JSON before pushing:

```
for f in data/*.json; do python -m json.tool "$f" > /dev/null && echo "ok $f"; done
```

- Keep each file under about 300 lines; split data into `-2`, `-3` files instead (the file lists in `js/data.js` name them).

## Smoke test before each deploy

1. Serve locally and open DevTools: no errors in the console on load.
2. Visit every tab; each shows data or a friendly message.
3. Map: the Routes list scrolls to the last item; tap a route (line highlights, popup opens), then **Clear selection**; open a pin, then **Clear selection**; toggle each layer.
4. Plan a trip: IT Park to SM City Cebu gives a transfer option; **Show on map** draws it; **Clear selection** removes it.
5. Bus tab: provincial routes are listed; selecting one turns on the Provincial bus layer.
6. Fares: pick two places and check the estimate; try Taxi; switch to Discounted.
7. Rename a data file temporarily: only that tab should show an error message.
8. Resize to a phone width: bottom tab bar and bottom sheet work; 44 px tap targets.
